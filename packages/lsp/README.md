# Shdr LSP transport (local spike)

`@shdr/lsp` is a **local, unshipped stdio LSP process** around the same `TypeScript7EditorAdapter` used by the VS Code fixture. It does not contain another shader checker. Protocol behavior was tested independently; the [`experiments/zed-shdr`](../../experiments/zed-shdr) dev extension also launches it when `apps/editor-fixture` is opened as a Zed workspace. The VS Code fixture continues using its existing adapter directly.

From the repository root:

```sh
pnpm build
node packages/lsp/dist/bin.mjs
```

The server reads and writes LSP `Content-Length` frames on stdin/stdout; initialize it with `workspaceFolders` or a file-backed `rootUri`. Process tests exercise open/full and incremental change/close, mapped diagnostics and hover, stale incoming versions, parse errors and recovery, project switching/config notifications, two distinct TypeScript configs under the **repository-root** workspace, unchecked-file errors, shutdown/exit and ordinary `.ts` isolation. Run `pnpm --filter @shdr/lsp test`.

[`src/project-discovery.ts`](src/project-discovery.ts) implements the [selection contract](../../plans/lsp-discovery/project-selection.md): nearest **including** ancestor config within each worktree, with distinct `excluded`, `invalid-config`, `no-config`, `not-on-disk` and `outside-workspace` results. The running server now owns a `TypeScript7EditorAdapter` per config and routes open documents to their project. It publishes an explicit `shdr-lsp` `SHDRLSP1001`–`SHDRLSP1007` error on an unchecked shader rather than advertising zero diagnostics; replacing an owner clears old diagnostics. If two URIs alias the same real file with different unsaved text, `SHDRLSP1007` explicitly rejects the second buffer rather than silently sharing one TypeScript snapshot. `workspace/didChangeWatchedFiles` re-resolves open shaders and increments the project epoch. If dynamic watch registration is supported, the server requests `tsconfig*.json`, `.shdr.ts` and `.ts` watches; the process tests send notifications explicitly. For clients that do not notify on filesystem changes, a subsequent shader open/edit re-selects its project and detects changes to an active config's own text, but **immediate** updates and inherited-config refresh are not promised without watched-file notifications.

**Remaining limits:** Only existing local `file:` `.shdr.ts` files in configured projects are checked; new unsaved files show an explicit unchecked status. Positions are UTF-16 original-source offsets. Project references are not traversed; no TypeScript inferred-project fallback is claimed. Checking remains synchronous on the LSP event loop: cancellation cannot interrupt a running check, and no background superseding/caching policy is implemented. Versioned documents reject stale **incoming** edits; watchers/config refresh were protocol-tested, not yet verified from Zed. The real Zed 1.21.0 screenshot covers only `apps/editor-fixture`; **`zed -n .` still cannot start the LSP** until the fixture-only dev launcher is changed in Phase 3. Neither the server nor the extension is distributed. [The integration decision](../../plans/_completed/next-milestone/editor-integration-decision.md) keeps the VS Code fixture on its own transport backed by the same adapter.
