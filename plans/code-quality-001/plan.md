# Code quality 001 — phased implementation plan

Implement the [readable generated-code spec](./spec.md) in a separate output-only PR. Readable local names are the **default**; redundant parentheses are removed only where both targets preserve the typed IR's parse tree and evaluation order. No DSL/API/IR-schema expansion, new shader diagnostics, uniform/resource renaming, or artifact-schema change.

## Phase 0 — Baseline, examples, and emitter contract

- Inventory call sites of `shaderLocalName` in `generate-glsl-expression.ts`, `generate-wgsl-expression.ts`, `generate-glsl-fragment.ts`, and `generate-wgsl-fragment.ts`. Record full-module versus standalone-expression generation: a standalone expression has no complete local symbol table and may keep ID-based names. Confirm existing generated bindings, uniform names, helper names, and target keyword/builtin constraints before choosing the common safe-name predicate.
- Save small pre-change GLSL/WGSL baselines for ordinary arithmetic and swizzles, right-nested f32 arithmetic, WGSL scalar/vector splats, guarded builtin calls, and hostile names. Identify exact-string tests in `generate-glsl-expression.test.ts`, `generate-glsl-fragment.test.ts`, `generate-wgsl.test.ts`, `backend-parity.test.ts`, and other generated-output tests. Keep tests that actually assert semantics rather than bulk-replacing snapshots to make them pass.
- Establish the desired output for a safe name (`inputMouse`), a fallback (`attribute`, `$color`, `café`, `shdr_coord`, `shdr_local_0`), and `inputMouse.x * gain`. List the reserved/generated namespaces and agree on a deliberately conservative identifier subset. The old alpha-renaming-identical-artifact test will be split into safe-name/readability and unsafe-name/fallback tests.

**Gate 0:** reviewed before/after examples, a common-name eligibility rule covering both targets, reserved-name inventory, and a focused test list. If target syntax or naming legality is uncertain, validate a raw GLSL ES 3.00/WGSL probe before treating it as safe.

## Phase 1 — Shared symbol-name plan, no parentheses changes

- Add a pure module-level `symbolId → emittedName` planner using the existing declaration `name` and `symbolId`. It must pre-reserve every `shdr_local_<symbolId>` fallback and every generated symbol/namespace. Use an authored spelling only when valid and unreserved in **both** GLSL ES 3.00 and WGSL; otherwise use the existing ID fallback. Plan once from the complete module; do not perform string replacements on emitted code or mutate IR. Both backends must compute the **same** deterministic plan from that IR.
- Pass the plan into both statement and expression generation. Declaration and reference must resolve through the same map (including aliases and multiple locals). Keep standalone-expression emission compatible: without a complete plan, references may continue to use `shdr_local_<symbolId>`; document that distinction in tests. Do not rename uniforms, generated entry/position bindings, helpers, or public uniform schema fields.
- Add exact-output tests for the `inputMouse` example and safe local references in both targets; fallback tests for target-only keywords, target builtins/types, generated names/prefixes, `gl_`, automatic uniforms, Unicode/`$`, and a name that resembles another symbol's fallback. Test a shader with several locals including mixed safe/unsafe names and a generated helper. Check no collisions, declaration/reference agreement, alpha-renaming behavior, stable repeated output from frozen IR, and no new source diagnostics.
- Compile these generated examples in real WebGL 2 and as WGSL shader modules on a real browser WebGPU device. A target compile failure is a naming-policy bug: tighten the common predicate rather than accepting a target-specific spelling or adding an author-facing restriction.

**Gate 1:** readable names appear by default in complete GLSL/WGSL fragments; unsafe names fall back without changing source acceptance; both targets compile and the existing TypeScript/core/CLI diagnostic ownership remains unchanged. Parentheses are still the old, conservative output so naming errors are isolated from precedence errors.

## Phase 2 — Precedence-aware expression emission

- Introduce explicit precedence/parent-context rules for atom, call/postfix/swizzle, unary, `*`/`/`, and `+`/`-`. Render a child with parentheses only when necessary to preserve its IR grouping. A binary **right** child at the parent's precedence stays grouped for _all_ operators, including `a + (b + c)` and `a * (b * c)`; a binary left child can use the targets' left association where legal. Parenthesize a lower-precedence child (`(a + b) * c`) and uncertain swizzle/unary receivers. A call argument's commas already delimit its expression, subject to target grammar. Never flatten or reorder expressions to improve appearance.
- Keep GLSL and WGSL lexical differences, numeric literal f32 spelling, WGSL explicit splats, `smoothstep`/guarded-builtin helpers, and constructed fragment positions intact. Share precedence _policy_ where useful, not completed shader-text rewrites. Examples such as `inputMouse.x * gain` should be readable without changing the target-neutral IR.
- Build a focused matrix in both expression emitters: all supported binary operators and scalar/V2/V3/V4 shapes, mixed precedence, right-nested equal precedence, unary negation, swizzle chains on locals/uniforms/calls, constructors, nested calls, splats and guarded helpers. Keep exact tests for grouping-critical expressions as well as reduced-parentheses examples. Confirm the generated text parses in real GLSL ES 3.00 and WGSL; keep parentheses wherever either grammar is uncertain.
- For sensitive finite f32 values, compare rendered output to a pre-change baseline where feasible, especially right-nested arithmetic and vector/scalar operations. Do not equate a text snapshot or a passed WGSL module compilation with semantic pixel parity.

**Gate 2:** the output is visibly less parenthesized while the parsed grouping/evaluation order is unchanged in both backends. All naming, raw-target compilation, and original-source diagnostic tests from Gate 1 continue to pass.

## Phase 3 — Integration, regression, documentation, PR

- Exercise the full fragment/compiler artifact path through CLI checks, static Vite transforms, the REPL, and the standalone runtime. Verify the production static bundles still exclude the compiler/authored-source execution and that bindings, helper selection, and artifact JSON metadata are unchanged. Compare real WebGL pixels with **presented WebGPU pixels** for finite, non-degenerate examples; include at least one shader exercising safe authored names and nontrivial grouping, plus a fallback-name shader. Use tolerances and pinned inputs rather than claiming cross-GPU bit identity.
- Update generated-code fixtures and examples intentionally (especially `backend-parity.test.ts`'s previous all-name alpha-equivalence assertion); retain invariant tests for identical IR → identical GLSL/WGSL, frozen IR, and one target-neutral name mapping. Confirm original-source core/CLI/TypeScript 7 diagnostic ranges and hovers and ordinary `.ts` ownership have not changed; run the **real** VS Code UI suite separately from adapter tests. Update user-facing examples only where they show outdated generated text.
- Run `pnpm build`, uncached workspace checks (e.g. `pnpm exec turbo run check --force` plus `pnpm shdr check`), `pnpm test`, `pnpm --dir apps/editor-fixture test:editor`, Prettier, and `git diff --check`. Review the final diff for accidental lowering/IR/runtime changes, changed emitted entry/binding names, loose keyword allowlists, or broad snapshot churn. Stop on target-validation or presented-pixel failures; do not paper over them by widening the language.

**PR gate:** the complete [spec](./spec.md) holds on both GLSL ES 3.00/WebGL 2 and WGSL/WebGPU, including authored-name fallback and grouping-sensitive cases. The only intended externally visible change is the readability of generated shader **text**; shader acceptance, original diagnostics, uniform interfaces, static-consumer boundary, and finite rendered behavior remain stable.
