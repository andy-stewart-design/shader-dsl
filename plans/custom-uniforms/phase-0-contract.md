# Custom uniforms — phase-0 typed contract and layout

Status: gate 0 design, **not implemented**. The [feature spec](./spec.md) is authoritative; the [plan](./plan.md) records implementation gates. [`contract-draft.ts`](./contract-draft.ts), [`contract.typecheck.ts`](./contract.typecheck.ts), and the `.shdr.ts` [fixtures](./test/fixtures/) type-check against TypeScript 7 with `pnpm exec tsc --noEmit -p plans/custom-uniforms/tsconfig.typecheck.json`. The draft signatures are **local compile-only declarations**, not new runtime exports or proof that the current compiler accepts these files. They import the real workspace's `Expr`/artifact/renderer option/result types; phase 1/2 must replace the draft with public types and repeat the tests against actual exports and TypeScript 7 editor quick info.

## Authored and consumer types

- `shdr` adds `defineUniforms` with `u.f32`, `u.vec2`, `u.vec3`, `u.vec4` (no `float` alias). Each builder call describes one static default and its type. `UniformDefinition<S>.createFragmentShader(callback)` and `createFragmentShader(callback, { uniforms: definition })` infer the **same** schema and callback `DefaultUniforms & { [key]: Expr<...> }`. The original `createFragmentShader(callback)` remains valid with no custom schema. The chained form is the introductory example; the named form is not a separate compiler/backend semantic path.
- `StaticArtifact<S>` is the existing serializable dual-target artifact with a **type-only invariant schema marker**; defaults are values in artifact metadata, not in the type identity. That means shaders with identical names/types and different defaults are compatible for typed `setShader`. The marker must not be a runtime symbol or prevent JSON serialization. Vite's authored import retains `S`; the optional `@shdr/core/browser` compiler returns a schema-erased `DynamicArtifact` because arbitrary source text cannot be statically known. The actual export names can follow the established `CompiledFragmentArtifact` name; the critical contract is the typed/erased distinction.
- The existing plain `CompiledFragmentArtifact` remains a usable schema-erased input for legacy code without constructor uniform overrides. Typed shader imports select the static overload; compiler-created dynamic artifacts can use runtime-checked constructor overrides. A plain artifact requires explicit erasure/narrowing to opt into the dynamic override path, avoiding a permissive fallback overload that would silently accept invalid values on a typed static shader. Gate-0 negative tests check wrong names/types/tuple lengths and incompatible `setShader` schemas; phase 1/2 must re-run them against real package exports to catch TypeScript structural-widening loopholes. Neither typed nor dynamic `setShader` returns a new renderer handle.
- `setUniforms` is a synchronous all-or-nothing partial patch. Typed values are JS `number` for `f32` and readonly fixed-length numeric tuples for vectors; dynamically compiled schemas allow numeric/tuple shapes but check the actual name and type at runtime. `resetUniforms(...names)` accepts zero or more current custom names and returns `void`. Both methods leave drawing to the next animation frame or explicit `draw()`. Creation-time `options.uniforms` is a partial first-shader override, applied **before** the first frame. It persists on the currently installed shader until reset/replacement but does not carry over unless the host explicitly calls `setUniforms` for that key.
- Invalid host values/names, including reset of an unknown name, throw `ShdrRuntimeError` with a new `"uniform"` kind; invalid creation-time values reject creation before its first frame. Invalid artifact metadata uses the existing `"artifact"` kind. Values and exact-length vectors must be finite before and after f32 conversion; ordinary f32 rounding (including `0.1`, and tiny values rounding to zero) is allowed, but overflow to infinity is rejected. Patches are copied so later mutation by the host cannot change submitted data. Generated-shader errors stay backend errors, while source errors stay original-source compiler diagnostics. No user-supplied automatic `resolution`, `mouse`, or `time` keys.

## Artifact and binding layout

Extend the JSON-serializable artifact **additively** with ordered custom schema entries (name, `f32`/`vecN` kind, and literal default value) plus target-specific referenced-name lists. For example, a fragment that uses only `color` may emit:

```ts
custom: {
  declarations: [
    { name: "color", type: "vec3", default: [0, 0, 1] },
    { name: "dpi", type: "f32", default: 12 },
  ],
  referenced: { glsl: ["color"], wgsl: ["color"] },
}
```

This is a data-shape sketch, not an implemented export. An absent custom section means no custom uniforms, preserving old artifacts. Use declaration order for deterministic offsets and generated identifiers; preserve original names in metadata and diagnostics. The public artifact describes **all** declared fields even if unused, so the host can update them; GPU binding is necessary only for referenced fields. Validate duplicate/invalid/reserved names, kinds, default shapes/numbers, reference subsets and ordering before allocating a candidate. Do not claim that metadata can prove arbitrary generated source is trustworthy; use compiler-produced metadata and let backend shader/pipeline validation surface source mismatches.

- **WGSL/WebGPU:** retain automatic uniforms in group 0 at their existing fixed bindings 0/1/2. Reserve group 1 binding 0 for a single `var<uniform>` buffer containing a generated struct of **all** custom fields in declaration order, only when at least one custom field is referenced. Generate safe internal member names and map the source names through artifact metadata. For f32, vec2, vec3 and vec4 the field sizes are 4/8/12/16 bytes and alignments are 4/8/16/16 bytes respectively. Place each field at `roundUp(fieldAlignment, endOfPreviousField)`; pad the allocation to at least 16 bytes and to the struct's alignment (16 minimum for this buffer). A `vec3` at offset 0 followed by an `f32` at offset 12 fits in 16 bytes; two `vec3` values begin at offsets 0 and 16. No arrays, matrices or nested structs in this slice. Validate these offsets with generated WGSL/pixel tests in phase 2 rather than treating a static layout calculation as GPU evidence. If no custom field is referenced, do not declare/bind group 1; a shader using only custom fields can still have an otherwise empty group 0.
- **GLSL/WebGL:** emit individual target-specific `uniform float/vecN` declarations only for referenced custom fields under collision-proof generated names (e.g. by declaration index). Resolve active locations from the linked program; an optimizer may remove an unused location, which does not remove the field from the public schema. Set the appropriate scalar/vector uniform on each draw where active. Do not impose WebGPU buffer padding on host values.
- **No shader parsing at runtime:** the compiler's target-neutral declaration/use data produces both target sources and the artifact metadata in one lowering. Runtime WebGL and WebGPU read metadata and use their own binding mechanics. Do not introduce a shared GPU resource manager, opposite-backend value imports, or parser/compiler imports in static consumers. Bundle/source-map audits remain part of the implementation gates.

## Replacement and concurrency

Resolve a candidate's values from **its** defaults, then apply only current persistent host overrides matching both the name and kind. A successful install prunes overrides missing or type-changed in the new schema; creation-time values are not sticky. An overridden field unchanged in kind retains the most recent `setUniforms` value even if the candidate's default changes. `resetUniforms` removes that sticky value and restores the installed shader's own default. While asynchronous preparation is in flight, value updates and resets affect the installed shader; before the candidate's **first real draw**, resolve again from the latest matching host overrides, not a stale snapshot. Only a successfully drawn candidate commits its shader, schema, values and pruned override map. Failed or superseded installs must leave the old shader and overrides intact except for legitimate concurrent host changes. Preserve the existing `ShaderInstallResult`, previous-frame guarantee (on a valid unchanged surface), RAF/manual-draw rules and terminal-loss behavior.

## Gate 0 evidence and remaining work

The TypeScript 7 probe proves both authored forms can infer `Expr<Vec3<F32>>`, `Expr<F32>` and default uniforms; that static imports carry schema types; that wrong host values and different replacement schemas produce compile errors; and that the dynamic editor mode accepts schema-changing artifacts with runtime validation. It is not a compiler, editor-adapter, Vite or GPU test. Phase 1 must verify real original-source diagnostics and hover using the actual TS7 adapter; phase 2 must prove real WebGL and **presented** WebGPU pixels, including alignment, first frames, failure preservation and in-flight updates. No extra per-frame canvas DOM attributes.
