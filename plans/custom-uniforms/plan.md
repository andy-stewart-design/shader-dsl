# Implement custom f32 uniforms

Status: gate 0 and phase 1 implemented locally; phases 2–3 **not implemented**. The [custom-uniform contract](./spec.md) is authoritative. The [phase-0 decisions](./phase-0-contract.md) and [type-checked draft](./contract.typecheck.ts) record this gate. Extend the existing workspace-only, dual-target fragment artifact and separate WebGL/WebGPU runtimes; do not add textures, arbitrary resources, transparent output, new scalar types, native runtimes, automatic backend fallback, or publication. Preserve unrelated in-progress changes. Review each gate before widening scope.

## Starting point and invariants

- [`shdr`](../../packages/shdr/src/dsl.ts) currently accepts `createFragmentShader(callback)` with only the automatic `resolution`, `mouse`, and `time` uniforms. The parser requires a direct default-exported call, one block-bodied arrow callback, and `({ coord, uniforms })` exactly. Source diagnostics and the TypeScript 7 editor adapter must remain in parity as these restrictions are extended.
- [`@shdr/core`](../../packages/core/src/compile-fragment-artifact.ts) lowers once, emits GLSL and WGSL, and derives per-target automatic bindings from target-neutral IR. [`@shdr/vite`](../../packages/vite/src/index.ts) exports static artifact data; `@shdr/core/browser` compiles edited source on demand. Neither route executes the authored `.shdr.ts` file, and static consumers must not bundle the parser/compiler.
- [`@shdr/runtime/webgl`](../../packages/runtime/src/webgl.ts) and [`@shdr/runtime/webgpu`](../../packages/runtime/src/webgpu.ts) already own dedicated opaque canvases, render on creation, and atomically install replacements. Existing default-uniform semantics, WGSL group 0 bindings 0/1/2, explicit backend selection, supersession, failure preservation, manual drawing, and terminal loss stay intact. Custom uniforms are values supplied by the host, **not** test-facing DOM instrumentation.

## Gate 0 — freeze types, artifact metadata, and GPU layout

1. Write compile-only TypeScript 7 sketches using the **real workspace imports** for both authored forms: `defineUniforms(...).createFragmentShader(callback)` and a same-file `const uniforms = defineUniforms(...); createFragmentShader(callback, { uniforms })`. The two forms must contextually type `uniforms.color` as `Expr<Vec3<F32>>`, its components and `uniforms.dpi` as `Expr<F32>`, and preserve the inferred schema through an imported `.shdr.ts` artifact. Retain `createFragmentShader(callback)` for shaders with no custom declaration. The runtime stubs still throw when authored source is executed without transformation.
2. Specify a small serializable artifact extension: an ordered, complete set of custom names, f32/vector types, literal defaults, and the per-target **referenced** subset. Both source forms must yield the same artifact. Keep automatic binding metadata distinct from custom declarations and distinguish static typed artifacts from schema-erased browser compilation. Decide the internal WebGPU custom-binding/packing layout and WebGL uniform naming here (including alignment and inactive uniforms); do **not** silently repurpose WGSL's fixed automatic group 0 slots. Document a deterministic metadata validation rule and how malformed artifacts fail before rendering.
3. Type creation-time `options.uniforms` as a partial override, `setUniforms` as a partial value patch, and `resetUniforms(...names)` as zero or more declared names. Map `f32` to `number` and vectors to exact-length numeric tuples. Prove with negative type tests that wrong names, scalar/string values, and vector lengths are rejected; same-schema `setShader` accepts different defaults, but a different schema cannot silently retain a statically typed renderer. Explicitly design the schema-erased live-editor path with runtime validation without widening the typed path by accident through structural TypeScript assignment. Do not add a newly typed handle or invalidate old handles.

**Gate 0 acceptance:** TypeScript 7 draft type tests cover both authoring forms, hover/quick-info expectations, static import typing, renderer options/updates/resets, same-schema replacement and the erased dynamic path; the artifact and GPU layout are documented before compiler/runtime work. Stop if the examples require editor-only type magic, executing authored files, or bundling compiler code into static renderers. **Complete:** run `pnpm exec tsc --noEmit -p plans/custom-uniforms/tsconfig.typecheck.json` and `node plans/custom-uniforms/verify-quick-info.mjs`. The signatures are compile-only drafts; repeat these assertions against actual workspace exports in phases 1–2.

## Phase 1 — parse, lower, and emit both targets

1. Extend `parse-shader-file.ts` and the import/syntax validators to recognize only the supported direct `defineUniforms((u) => ({ ... }))` declaration, its explicit same-file `{ uniforms }` link, or the direct `defineUniforms(...).createFragmentShader(callback)` default export. Normalize both to one shader declaration before semantic lowering. Do not permit alias captures, arbitrary builder chains, computed names, duplicate/reserved `resolution`/`mouse`/`time` names, nonliteral defaults, incorrect arities, nonfinite/out-of-f32-range values, or ambiguous declarations. All invalid forms receive original-source Shdr diagnostics; do not evaluate ordinary JavaScript or silently fall back to TypeScript behavior.
2. Accept the agreed callback forms: `({ uniforms })` without `coord`, expression-bodied arrows as well as block bodies, and the existing `({ coord, uniforms })` form. Preserve the required `Vec4<F32>` result and old behavior. Update normalized shader syntax, static validation, virtual-source/range mapping, target-neutral IR, lowering and tests so custom references retain their declared type and declaration identity without embedding GLSL/WGSL layout in IR. Generate target-specific declarations from IR, bind only referenced custom uniforms, and derive complete schema/default metadata from the same lowering pass rather than parsing generated output.
3. Update `shdr`'s DSL/public types, Vite transform and opt-in browser compilation to emit the identical serializable artifact. Update the TypeScript 7 editor adapter and language-service fixtures for valid custom property hovers and matching invalid-source diagnostics; retain ordinary TypeScript behavior outside `.shdr.ts`. Preserve the ability to import shader modules statically without shipping compiler/parser or runtime DSL stub values.

**Gate 1 acceptance:** core tests cover both equivalent authoring forms; scalar/vec2/vec3/vec4 defaults, unused declarations, automatic/custom references, deterministic ordering and binding subsets; source ranges for invalid names, literals, callbacks and links; and unchanged shaders without custom uniforms. Vite unit/dev/build and browser-compiler parity tests agree byte-for-byte on artifact fields for the same source; static production bundles exclude parser/compiler. Both GLSL and WGSL must compile real samples before proceeding; editor type/diagnostic parity and `shdr check` pass. **Complete locally:** generated WebGL/WGSL compile in Chromium/SwiftShader; browser compiler, Vite build/dev/static import and TypeScript 7 fixtures pass. Runtime custom binding/pixels remain phase 2.

## Phase 2 — isolated renderer values and lifecycle

1. Validate the artifact schema/defaults and host values at each renderer boundary (including malformed input from plain JavaScript): known names, exact vector lengths, finite numbers without f32 overflow (normal rounding is allowed), and atomic all-or-nothing patches. Install serialized defaults before the constructor's first draw; layer optional creation-time overrides on that shader only. Store copied values, not caller-owned mutable arrays. `setUniforms` updates values without recompilation or scheduling an extra draw; `resetUniforms("dpi", ...)` clears named overrides and restores current defaults, and no arguments resets all. `{ animate: false }` observes changes on the next `draw()`.
2. Implement one shared host-side resolution of defaults, creation values and persistent `setUniforms` overrides, with backend-specific WebGL uniform writes and WebGPU packing/buffers. Preserve fixed automatic binding slots and selective GPU allocation. Document/test any f32 conversion and vector padding; never infer bindings from GLSL/WGSL text. Resource creation and cleanup remain backend-owned, and WebGL-only/WebGPU-only imports remain isolated from each other and the compiler.
3. On `setShader`, keep the renderer object stable. Prepare the candidate using its defaults and the **latest** explicitly set overrides whose names and types match; do not carry creation-only overrides or keep incompatible overrides dormant. While an install is pending, patches/resets apply to the installed shader and must be reflected in the candidate's first real frame if it commits. Failed or superseded installs retain the prior shader, values and overrides except for valid concurrent host updates. Respect generation checks, WebGPU validation-scope serialization, offscreen preflight, cleanup, context/device loss and existing error channels. Replacing with a shader containing no custom declarations remains supported.

**Gate 2 acceptance:** independent Chromium/SwiftShader tests import each renderer and assert **real WebGL pixels and presented WebGPU pixels** for default first frames, constructor overrides (no first-frame flash), animated and manual updates, reset-one/many/all, unused/bound subsets, and f32/vector packing. Cover compatible and incompatible schema replacements, changed defaults, rejection of bad whole patches, in-flight updates/resets, overlapping installs, failed replacement preservation, terminal loss/disposal, and absence of test-only per-frame canvas attributes. Inspect isolated production bundles for no opposite backend or compiler/parser.

## Phase 3 — exercise hosts and document the feature

1. Add small Vite fixture shaders using **both** authoring forms and representative default/override/reset/same-schema replacement flows. Prove static imports preserve typing, both targets render real pixels, and Vite dev edits rebuild both outputs without pulling compiler code into the static app.
2. Extend REPL browser regression coverage to edit declarations/defaults in dynamically compiled source, replace with different names/types on the same canvases, and verify per-target pixels and last-good-frame behavior. Exercise the erased runtime-value path without adding a general-purpose uniform-control panel or moving REPL-specific coordination into the public runtime. Existing pointer/time sharing, unavailable-WebGPU fallback, diagnostics and target-specific statuses must continue to work.
3. Update the root language reference and `shdr`, Vite, runtime and REPL docs to show both authoring forms, automatic versus custom uniforms, static defaults versus instance/host overrides, manual draw and reset, schema-changing dynamic edits, and rejected dynamic defaults. Keep the completed runtime-v1 contract historically accurate; link to this feature rather than rewriting its scope.

**Final gate:** run `pnpm build`, `pnpm check`, `pnpm test`, `pnpm ci:check`, focused core/type/editor/Vite/runtime/REPL checks, Prettier, local link verification, and `git diff --check`. Verify genuine WebGPU presented pixels, not only shader-module validation. Stop for review before textures, other custom resources, publishing or scope expansion; do not exclude unrelated user changes from a PR without permission.
