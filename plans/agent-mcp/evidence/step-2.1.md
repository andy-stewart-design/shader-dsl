# Step 2.1 — Catalog, validation, and result contracts

- Implemented atomic `AgentBridge.updateTools(nextTools)` with monotonically increasing catalog versions, helper acknowledgements, invalid-replacement rejection, and a bounded acknowledgement deadline. Discovery/description report the current version; invocation requires the current session/version. Replacing a catalog rejects outstanding old-catalog calls without replaying them. Registration/replacement alone never invokes handlers.
- Shared synchronous JSON Schema 2020-12 validation permits local references only, bounds catalogs before compilation, and checks names/duplicates/arguments at both boundaries. Browser handshake/message parsing validates protocol metadata and byte limits. Ordinary JSON remains text; reserved result envelopes reject unsupported versions, MIME/base64/metadata, per-image sizes, and total serialized sizes. Images remain actual MCP image blocks with readable metadata. Page error categories are allowlisted and mapped to bounded messages rather than forwarding arbitrary exception text.
- Final checks passed: package `format`, `check`, `build`, and `test` (**23 tests in 5 files**), plus demo `check` and `build`. Log: `/tmp/agent-bridge-2.1-final.log`. Tests reuse the existing Vitest/fake-socket/built-CLI loopback seams; no new framework, dependency, browser harness, download, deployment, agent configuration, or live model test was added.
- Focused proof includes atomic browser replacement and handler non-invocation on rejected requests, built MCP catalog v1→v2 discovery/description, stale/removed/invalid call rejection before dispatch, invalid replacement preserving the catalog, old in-flight result invalidation, handler-message redaction, local-vs-remote schema references, and exact image/whole-result size boundaries.
