# Step 1.1 — Thin bridge and React demo

- Implemented `packages/agent-bridge`: public protocol/browser/server exports and stdio CLI, exact-origin/token pairing, loopback WebSocket dispatch, input schemas, and MCP text/image conversion. Integrated the user's React Vite demo with read-state and generated-image tools, connection status, pairing, and disconnect; no REPL or runtime-control tools were added.
- Passed package `check`/`build`/`test` (8 focused tests) and demo `check`/`lint`/`build`. Earlier composition checks also passed workspace check/build and frozen offline lockfile verification; final runtime fixes were followed by the focused package/demo checks. Those automated checks used no browser harness, browser download, live model call, agent configuration change, or deployment; user-assisted live results are recorded separately below.
- Fixed immediate review issues: old-socket callbacks affecting a newer connection, raw handler-error forwarding, unsupported initial catalog versions, oversized browser responses, and malformed-result exceptions escaping the server callback. The existing smoke tests are not exhaustive coverage of these paths or the later security matrix.
- **User-assisted localhost proof:** the user paired the demo after Pi reload, discovery returned both application tools, and `demo_get_state` reported `demoState: ready`. `demo_capture_image` delivered a real model-visible 640×360 image: a purple left panel with an inverted white triangle and a green right panel with a dark circle, plus the expected labels. This verifies the live local agent → helper → page → image path, not merely image-shaped JSON.
- **Disconnect/re-pair passed:** after the user disconnected, connection info had no active session and returned a fresh pairing link. The user reconnected; the helper assigned a different session identity, and `demo_get_state` succeeded again with `demoState: ready`. Step 1.1's local prototype completion gate is satisfied. HTTPS/LNA/CSP and deployed image acceptance remain Step 1.3; resume/cancellation/catalog replacement and broader failure coverage remain Phase 2.

Prototype caveat: the WebSocket parser has an 8 MiB transport backstop; unauthenticated messages are rejected above 4 KiB at the message boundary, with bounded sockets and a 5-second authentication deadline. This is not a claim of a 4 KiB pre-allocation parser bound or production hardening.
