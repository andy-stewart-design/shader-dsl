## Step 4.2 downsampling regression investigation and fix

The post-redeploy live proof isolated the failure rather than showing a bad shader or bad metadata. In one refreshed session, the five-tool catalog and the default source were correct (`const uv = coord.xy / u.resolution;` with the gradient body), with applied/draft revision 0 and WebGPU canvas 1209×1209. `capture_preview({ expectedAppliedRevision: 0 })` returned a valid 512×512 PNG and metadata reporting `backend: "webgpu"`, encoded `width`/`height` 512×512, and native `identity`/`canvasWidth`/`canvasHeight` 1209×1209, but the PNG was black apart from a tiny dither border. The same session with `maxDimension: "native"` returned the correct 1209×1209 gradient. The native PNG was only resized externally with macOS `sips -Z512` for diagnostic viewing; that diagnostic 512px image remained visibly correct. This proves the bug was the app's GPU-canvas-to-2D downsample read after the presented WebGPU buffer had been cleared, not all-black shader output, encoder metadata, or the native path.

The fix in `preview/capture-canvas.ts` is blob-first: encode the renderer canvas natively with `toBlob()` first, decode that captured PNG using `createImageBitmap` (with an HTML image/object-URL fallback), then draw the decoded snapshot into an unattached bounded 2D canvas and encode only that target. The native path and identity dimensions remain native; only encoded dimensions are bounded. Bitmap/object-URL cleanup is in `finally`, and abort/deadline checks cover native encode, decode, snapshot draw, and final encode. The 4 MiB PNG limit, 64–2048/native bounds, aspect ratio, and no-upscale behavior remain enforced. `snapshot.ts` passes the capture signal through the production helper, so the existing capture identity/stale/cancel/deadline guards remain in force.

The focused regression now models the failure seam: the source canvas's native blob contains a `native-captured-pixels` token, the test decoder exposes that token as the decoded bitmap, and the resized target can only produce `resized-from-native-captured-pixels`; the source canvas is asserted never to be passed to `drawImage`. This is pixel-provenance/order coverage, not only a draw-call counter. Native, resize/aspect/no-upscale, bounds, cancellation/deadline, metadata, identity, and the prior 4.1/authoring tests remain in the native Node suite: `pnpm --filter repl-web test` passes 75/75. `pnpm --filter repl-web check`, `pnpm --filter repl-web lint`, `pnpm --filter repl-web build`, and `pnpm --filter repl-web build:preview-probe` also pass (the app build retains existing dependency `use client` warnings; the probe retains its existing chunk-size warning).
