**Target for Phase 1** (names only): `vec2 inputMouse = vec2((u_mouse).x, ((u_resolution).y - (u_mouse).y));`, with `float gain = u_time;` and `vec4(((inputMouse).x * gain), ...)`. WGSL likewise declares `inputMouse` and `gain` but keeps its old grouping. **Target for Phase 2:** `vec2 inputMouse = vec2(u_mouse.x, u_resolution.y - u_mouse.y);` and `vec4(inputMouse.x * gain, ...)` (and target-specific WGSL spellings). The right-nested arithmetic above must remain grouped, e.g. `a + (b + c)` and `a * (b * c)`; it must not become a left-associated string.

## Common safe-name policy to implement

Use a conservative _intersection_, not independent per-backend decisions:

1. Start with an ASCII identifier candidate matching `^[A-Za-z_][A-Za-z0-9_]*$`. Reject **any `__` substring** (important even when the regex accepts it), every `gl_` and `shdr_` prefix, and all pre-reserved fallback spellings. The two target specs have different identifier/keyword rules; accepting `$` or Unicode in Shdr source does not require preserving those spellings in shader output.
2. Reject the union of GLSL ES 3.00 and WGSL keywords/reserved words, builtin functions, constructors/types and names that could shadow target-generated calls, plus generated globals/entry names, `u_resolution`, `u_mouse`, `u_time`, WGSL uniform/struct/helper names, and `main`. Reserve these even if their corresponding uniform/helper is not emitted for a particular shader so unrelated changes cannot rename existing locals.
3. Keep the entire reserved set and predicate tested, with representative target-only words (`sampler2D` and `vec2` fail in GLSL; `let`, `fn`, `alias`, `override` fail in WGSL), generated bindings, `a__b`, `gl_Foo`, and safe `inputMouse`. Do not rely on the finite probe list as a complete keyword/builtin vocabulary; audit the [GLSL ES 3.00 specification](https://registry.khronos.org/OpenGL/specs/es/3.0/GLSL_ES_Specification_3.00.pdf) and [WGSL identifiers/keywords](https://www.w3.org/TR/WGSL/#identifiers) when implementing the denylist, and fail closed for unverified names.
4. Source declarations remain legal under today's Shdr rules. Unsafe output spelling gets the existing `shdr_local_<symbolId>` fallback; one module-wide mapping feeds _both_ target emitters. No new `SHDR` diagnostic and no change to authored uniform field names.

### Raw-target spot checks

Chromium **153.0.8010.12** / SwiftShader: WebGL 2 fragment shader `#version 300 es` compiled with `gl.compileShader`; WebGPU `device.createShaderModule(...).getCompilationInfo()` inspected for errors. Each identifier was tried as a local `float`/`f32` in an otherwise valid fragment shader. ✓ means module/shader compilation succeeded; ✗ means a reported shader compilation error. These are syntax/validation probes, **not** rendered pixel tests.

| Identifier                                          | GLSL | WGSL | Policy                                                                                                                                   |
| --------------------------------------------------- | :--: | :--: | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `inputMouse`, `_leading`                            |  ✓   |  ✓   | May preserve after namespace/denylist checks.                                                                                            |
| `attribute`                                         |  ✗   |  ✗   | Fallback.                                                                                                                                |
| `sampler2D`, `vec2`                                 |  ✗   |  ✓   | Fallback: target disagreement.                                                                                                           |
| `let`, `fn`, `alias`, `override`                    |  ✓   |  ✗   | Fallback: target disagreement.                                                                                                           |
| `gl_Foo`, `a__b`                                    |  ✗   |  ✓   | Fallback: GLSL reserved/implementation behavior.                                                                                         |
| `__private`                                         |  ✗   |  ✗   | Fallback.                                                                                                                                |
| `sin`, `texture`, `main`, `u_mouse`, `shdr_local_0` |  ✓   |  ✓   | **Still reserve**: builtin call, generated symbol/entry, binding or fallback-name collisions. Mere isolated compilation is insufficient. |

Additional raw expressions compiled in both targets: `vec2(0.25).x` / `vec2<f32>(0.25f).x`, `(-vec2(0.25)).x`, `(vec2(0.25) + vec2(0.25)).x`, chained `.xy.y`, and right-grouped `0.25 + (0.5 + 0.75)` (target-appropriate f32 suffixes). This establishes a small positive grammar baseline; Phase 2 must separately validate representative generated modules and semantics. The GLSL ES 3.00 spec reserves double-underscore-containing identifiers for underlying software; Chromium's validator rejected `a__b` in this probe. Avoid that spelling rather than treating either behavior as portable.

- **Phase 2:** Update expression-level grouping assertions in `generate-glsl-expression.test.ts`, `generate-wgsl.test.ts`, `backend-parity.test.ts`, `math-builtin-ir.test.ts`, `math-builtin-parity.test.ts`, `mix-step-parity.test.ts`, and `vector-arithmetic.test.ts` where they assert old punctuation.
